## Cross-cutting finding that colours categories 10, 15 and 17

**Damage written onto ANOTHER PC never runs that PC's damage pipeline.** All three peer paths
— an ally's damage tray (`src/features/character/center/DamageTray.tsx:296-370`, `givePeer`),
the DM's monster action (`src/features/campaigns/encounter-monster-actions.tsx:369-388`) and the
DM's party card (`src/features/campaigns/party-encounter.tsx:1127`) — send
`{kind:"hp", operation:{kind:"damage"}}` to `writeCampaignCombatEffect`, whose reducer is
`reduceHpDelta` → `applyDamage` (`src/lib/combat-state.ts:323-331`, `src/features/campaigns/campaign-io.ts:958-983`).
The real pipeline, `reducePcDamage` (`src/lib/combat-transition.ts:85`: 0-HP death-save failures,
crit = 2, instant/massive death, Unconscious, consumed effects like Armor of Agathys, zero-HP
floors), has exactly one caller: the owner's own `takeDamage` (`src/lib/play/damage.ts:46`).
The concentration-save queue is filled only inside the owner's store `applyDamage`
(`src/stores/characterStore.ts:1530-1545`); the hydration of a peer write only _filters_ saves
already queued (`characterStore.ts:893-900`). Evasion's `save-damage-rule` is consumed only by
`resolveCombatDamage` (`src/lib/combat-resolution.ts:550`), which has **no production caller**;
the tray's multiplier ignores it (`src/lib/play/damage-tray.ts:378-399`). So a monster hit or an
ally's Fireball that drops a PC to 0 sets HP to 0 but adds no Unconscious, no death-save
failure, ends no Concentration and asks no concentration save. This is family **F1**.
