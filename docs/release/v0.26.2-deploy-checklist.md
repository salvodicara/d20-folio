## Rollback

Stored data is never rolled back: a Firestore import would erase every save made since the backup.
That path is the `live-data-migration` skill, with the owner's yes. The new client's data reads
fine in the live release (step 2a), so either option below is safe for stored characters:

- **Client only.** Firebase console → Hosting → release history → the 2026-11-25 release →
  «Rollback». The new rules stay, and they accept the old client's writes (draft, items #1250,
  #1320, #1413).
- **Whole release.** `gh workflow run deploy.yml --ref hotfix/shared-sheet-2026-11-25` redeploys
  `6fe669402` (its CI and Verify are green). It puts back the old Functions, the old rules and the
  old Hosting in one run, with a fresh backup first.

Neither is written down elsewhere: the Coordinator confirms the choice with the owner before
using one.
