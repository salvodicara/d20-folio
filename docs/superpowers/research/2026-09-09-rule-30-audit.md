## 1. The three findings that decide the block

1. **The app has no game to be cold about yet, and the parts it has are procedures.** Of the four
   permanent domains, the runtime today offers Account (seven sections), a roster with a creation
   wizard and an import review, a campaign page that is a membership form, and a library that is an
   authoring console; "At the table" says "Live play is not available yet" (RW §At the table;
   `src/features/identity/IdentityWorkspace.tsx:556-565`). The first screen after sign-in is the
   Account **Profile form** (RW §Account landing), where every reference lands on a campaign or a
   character home (RC §Job A: Roll20 Game Details "the first page new players see"; D&D Beyond
   "My Characters", RCH (e)). The mock lands on the campaign chronicle with the party and the next
   session (MW §1.1; `docs/program/reference/screenshots/campaign-desktop.webp`). **Rule 30 verdict:
   the mock follows, the app reinvents.** Priority M, S1–S4.
2. **Creation reinvents the one flow both binding references solve the same way.** Baldur's Gate 3
   and D&D Beyond show a short, filtered choice with its meaning beside it, a recommended default,
   a required-state marker on the control and the consequence before the click (PD §3–§4, patterns
   1–12). The runtime shows native `<select>`s with 24 species and 62 backgrounds in one flat list,
   an empty description for every class and species until this task, a version-and-catalogue
   provenance line above each choice, a path-and-code string as the error text, a JSON dump under
   every option and a metric "Walking: 9.14 m" in the EN review (RW §Creation). The
   mock's builder (five steps, "Partenza rapida · opzioni proposte, sempre modificabili", a live
   aside, one validation sentence per field) is closer to the references than the app is (MW §2.9).
   **Verdict: reinvents.** Priority M, S1, S3.
3. **The library and campaign surfaces speak the engine's language.** "Record version", "Declared
   effects … These fields describe the content; they do not apply it", "Unsupported declarations",
   "Check operation receipt", "Encounter preparation ID", "Campaign code" showing a Firestore id
   (RW §Library, §Campaign hub; CI §2.2). Every reference editor starts from an existing entry and
   a two-field basic form (RL §Dominant 2), and no reference exposes provenance strings, ids or
   payload JSON to a player (RL §1–§2; RCH (a)). **Verdict: partial on structure, admin on
   register.** Priority D (library), M (campaign hub), S2–S4.

The rest of this document is the table those three findings summarise, then the superfluous list,
the ordering by story, and the consequences already implemented in Claude's lane.
