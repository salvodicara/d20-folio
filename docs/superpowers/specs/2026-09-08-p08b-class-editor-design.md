## Experience and facts

One LibraryDefinition/ClassData is authoritative. Preserve the Library sidebar, title, draft state,
version actions and common reader. Identity uses named hit die/abilities/two distinct saves and
ordered subclass schedule. Guided disclosure separates common acquisition, first-class acquisition,
multiclass acquisition and each stable level row. An ordered progression overview opens level details;
adding1/3/5, changing a level and explicit ordering never regenerate row/choice/option identities.
Root dependencies are pinned once with the shared picker. All acquisition scopes use the same
OriginFields composers, with names for parent choices/options and included versions. Programs,
resource bindings and composed costs use named references; internal identities are advanced read-only
information, not required user input. Casting policy and absolute row counts/slots have explicit
labels, units, zero and carry-forward explanations. No character advancement or spell-slot calculator.

Unknown/future/incompatible originals remain intact; malformed sections are preserved and blocked
from implicit replacement. Known edits spread unknown fields. Invalid references/costs/order remain
visible conformance diagnostics and cannot publish. No silent repair or unsupported execution claim.
Existing loaded/base/revision/envelope/receipt autosave remains sole persistence. Offline/conflict,
storage failure, identity changes and unknown writes preserve drafts and require exact reconciliation.
