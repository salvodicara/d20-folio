## Operation and authority

One immutable envelope contains opId (also intentId: no redundant identity), actor UID, exact target, original base revision, authority snapshot and typed payload. The UI creates it once per explicit save/assignment intent, before dispatch. Retries and timeout reconciliation reuse it; edits after conflict create a new intent only following an explicit decision. Attempt counters are local callback fences, not durable operation identities.

Notes retain their existing literal private paths. Their data gains revision and last operation identity; old text-only notes decode as revision zero. Character assignment remains in the owner character document with reciprocal roster and history. An operation receipt is immutable and owner-private, written atomically with the mutation. It stores the complete envelope and resulting revision; note text never enters campaign-public data. Receipt lookup precedes stale-base rejection so an already committed operation remains acknowledged after later edits. Same opId with different payload rejects.

Transactions read current auth authority, target, receipt and relevant character/campaign authority before writing. Notes compare note revision; personal notes also compare the exact character revision/currentAssignment; campaign notes compare campaign revision and DM/admin authority. Assignment compares character revision/currentAssignment and target campaign revision; old-claim recovery continues to be checked by rules at commit. All writes retain P02 ACL, blocked-account precedence and no fabricated consent. Rules verify atomic receipt linkage and version increment, with no downgrade to old unversioned writes. Import may initialize old-format notes only as part of creation of a new character; original archives remain untouched.

## State and offline

One controller owns pending, unknown, acknowledged, conflict, rejected and invalidated states. Timeout is unknown, never fabricated success/failure. Reconcile reads the authoritative receipt; absence permits retry of the identical envelope, never a new ID. Concurrent callbacks cannot roll back a newer outcome. Session generation fences unsent work and late acknowledgements. Changing auth/campaign/active character, inspected note target or remote authority invalidates the original intent; no automatic replay into a new context.

Pending envelopes, drafts and owner-only last verified note snapshots are retained in per-account browser session storage for reload recovery, excluded from URLs and other accounts. They are never a local authority for ACL or commit. A remounted owner editor can recover its local draft offline; any retry matches scope and rereads commit authority; obsolete context becomes invalidated and cannot submit. Offline permits draft editing and retained owner reads; saving shows waiting for connection. Reconnection enables explicit reconciliation/retry, not blind queued writes. Foreign/DM caches do not confer authorization. Revocation clears visible sensitive context; bytes already received cannot be retroactively revoked.

Conflict preserves the user's draft and shows the latest saved text alongside it. A single explicit review/rebase action accepts that current base before a new save; no silent overwrite. Unknown offers Check save; offline explains unsent status; acknowledged is based only on remote receipt. UI follows existing note editor composition, dark EN/IT, relevant desktop/phone matrix, no technical IDs, no new motion/shortcut switches.
