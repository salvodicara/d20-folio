## Experience and architecture

Use the existing Library editor, autosave/controller and immutable version repository. Enable
subclass authoring with a named parent class/version picker over actual accessible LibraryVersions.
Include the selected parent through includeOriginDependency and preserve the complete root closure.
Bind both dependency tuple and mechanicId; validate through conformClassPair before accepting a
selection. Distinguish equal names by version and provenance. Changing parent is explicit and keeps
existing progression/choices/unknown fields for review; never repair or regenerate their identities.
Display pinned parent and schedule, explain first acquisition and casting-only intermediate rows.

ClassFields is the shared progression/casting/acquisition authoring adapter; class-only identity,
starting/multiclass fields remain restricted to class. SubclassFields owns parent selection and
castingRelationship, then uses that shared adapter. OriginFields owns guided shared choices and
root dependencies; AdvancedFields owns generated IDs and named resources/programs. Internal IDs
are not required unexplained inputs. Preserve familiar form labels and progressive disclosure.

The authoring consultation shows how parent/subclass casting declarations compose: inherit keeps
parent; augment adds counts but inherits policy; replace supplies one policy for the owning class.
Multiclass contribution is explicitly declared and presented once, with Pact separate. This is
static definition composition, not character growth, a character store or encounter execution.
Unknown/future/incompatible content remains intact and visible; unsupported never gains an invented
computed result. Reuse recorded subclass creates an independent Library draft from its stable
version, while Duplicate uses the current draft. Copies never silently follow source edits.
