## Classes (exclusive)

| Class                                   | Meaning as applied                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **AUTOMATED**                           | On the live user path a single tap expresses intent and the consequences flow (state, resources, durations, log, undo) with an override; the seam is named. The live path for target-bearing rules is the legacy `CombatResolver`/`TurnEconomyProvider` inside a campaign encounter; the engine path is live only in solo play. Where a rule is AUTOMATED only on one executor, the split is recorded as **RC2** in the root-cause column (not as a downgrade), so the aggregation stays honest. |
| **MODELED-NOT-AUTOMATED** (MNA)         | Data/grant exists but the consumer is dead, the effect renders nowhere, a second manual toggle is required, or it works on only one executor **and that executor is not the one where the rule matters**. ## Root causes (as briefed; none added)

- **RC1** single-modeled-character assumption — stores/engine take one character; monsters are display data (`data/types.ts:2298-2388`, `automation-corpus.ts:368-373` marks `traits/actions/bonusActions/reactions/legendaryActions` as `IGNORE`); no monster action execution exists anywhere (`MonsterAttackEntry`/`MonsterSaveEntry` have zero consumers in `src/features`+`src/lib`); the DM-side "adversary" capability is damage/heal/condition **applied to** a monster (`features/campaigns/encounter-world-command.ts:224-236` takes `monsterId` as the target), never a monster acting; PCs live in their own character material, not the shared world (`lib/encounter-world-store.ts:1049-1170` party lease correlates two commits).
- **RC2** two-executor split — engine gate `features/character/center/tabs/PlayTab.tsx:470` `if (sheetCombat || !character) return null;` plus the exclusion predicates at `:488-540`; legacy `TurnEconomyProvider.tsx` (3045 lines) + `CombatResolver.tsx` (3064) own every targeted resolution; `combatStore` (`stores/combatStore.ts:99-222`) and the engine `TURN_ECONOMY_STATE_SCHEMA` (`types/turn-economy.ts:330-340`) are two writers of the same six turn facts.
- **RC3** outcome-independent commit — slot/cost is spent at cast, before any per-target outcome (`lib/mechanics-*` clause "slot-payment: automated" precedes "saving-throw: physical-input" for every spell in `docs/automation-coverage.generated.json`); Counterspell's "slot not expended" and Shield's retroactive miss cannot be expressed.
- **RC4** cost as scattered optional fields — `ResolvedAction.costsSlot/costTracker/resourcePayment/resourceCost/costEquipment/alternateCost` (`lib/smart-tracker.ts:694-738`); payment and slot claim sequenced by hand in `TurnEconomyProvider.tsx:928-960`.
- **RC5** no relational/tactical state model — the only per-pair facts are `CombatAttackTableFacts` entered per resolution (`lib/combat-test-context.ts:46-60`, defaults "clear sight, normal range, no cover" `:122-142`) and the `target-mark` payload (`types/combat-effect.ts:78-85`, scopes `marked|cursed|vowed` only). No adjacency/range/visibility/cover/engagement is retained; no grappler/charmer/frightened-source/help/vex/sap links.
- **RC6** no trigger/reaction window model — reactions "NEVER dispatch from a board tap" (`PlayTab.tsx:472-486`); the only reaction runtime is the damage-entry prompt (`lib/damage-reaction.ts:104-292`, dice-rolling reactions excluded `:18-24`); off-list reactions are a "Mark used" row (`PlayTab.tsx:1266-1290, 2405-2440`); legacy turn boundaries exist only for the own participant (`types/character.ts:1029` `effectBoundaries` carry `round+phase`, no combatant); engine triggers are `turn-boundary/damage-taken/hit-points-zero/area-boundary/leave/...` (`lib/mechanics-trigger-schema.ts`) with `area-boundary`/`leave` fed by table pulses.
- **RC7** persistence — whole-object LWW combat writes (`stores/characterStore.ts:250-251, 331, 2864, 3331`); two condition representations (flat `session.conditions` strings + encounter `effectOps` `condition` payload, `types/combat-effect.ts:87-90`) reconciled by projection (`lib/condition-projection.ts`).
- **RC8** authorization duplicating game semantics — `firestore.rules:380-436` re-encodes the closed condition set (`coreConditions()`), the peer-writable combat keys allowlist and the encounter-epoch receipt predicate.
